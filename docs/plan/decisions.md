# Decisions

## Product decisions
| ID | Decision | Source |
|---|---|---|
| D-000 | Plugin for the Hermes ecosystem; dashboard only in the Desktop bottom status bar (click opens a popup); settings in the standard Hermes plugin settings; configurable scan interval, lead time, accounts | maintainer decision |
| D-001 | Reset Rescue covers **every** `openai-codex` account in the profile's credential pool from v1, the way already-admitted catalog plugins do (`plugin-catalog/quota.yaml`, `hermes-resetwatch.yaml`, `account-pool.yaml`, `hermes-monitor.yaml`). The pool is read read-only through Hermes' own `read_credential_pool('openai-codex')`; auth.json is never written, rows are never serialized, tokens never reach the Desktop, DTOs or logs. Refresh happens only through Hermes' own path, once per account per run on a 401. `credentialed_provider_request` (active sign-in) stays only as an automatic fallback when the pool slice is empty. No upstream Hermes seam or PR is part of the plan. Pool use is a disclosed deviation from catalog rule 11, with precedent in already-admitted catalog plugins. | maintainer decision |
| D-002 | Redemptions run for real from install. Two schedulers may target the same credit; duplicate notices and a split history are accepted, because the later POST meets an already consumed credit | maintainer decision |
| D-003 | Refresh on 401: once per account per run, through Hermes (`hermes auth refresh openai-codex <id>`) | maintainer decision |
| D-004 | Automatic redemptions are enabled right after install (`automatic_rescue` default true) | maintainer decision |
| D-005 | Demo rehearsals use real read-only GETs, cron and notices, and spend no credit | maintainer decision |
| D-006 | The repository is published only after the final review and the public scanner gate pass | maintainer decision |
| D-007 | Two expiry reminders per credit, each configurable in hours before expiry or off (0): first default 24 h, second default 1 h. Plus the success/failure notices of every redemption | maintainer decision |
| D-008 | Notices go to the messaging channel already set up in Hermes (its home channel, e.g. Telegram), through Hermes' own delivery (`hermes send` / native cron delivery). No new bot, token or service. The target is overridable in settings | maintainer decision |
| D-009 | Optional early redemption, OFF by default: when enabled, redeem the soonest-expiring available credit of an account when its weekly quota remaining is at or below X% (default 0%) | maintainer decision |
| D-009a | Early-redeem re-arm: after an early redeem succeeds (or is in flight/unknown) for an account, meta `early_rearm:<account_key>` = `spent` blocks further early redeems for that account until a fresh, readable reading shows weekly remaining above its threshold. Unknown or failed readings keep it spent. Lead-time and Redeem now are unaffected; the 15-min cooldown stays | maintainer decision |
| D-010 | The plugin never shows quota percentages per account. The popup lists only accounts with banked resets: how many, and each expiry in chronological order (soonest first), with its scheduled rescue time | maintainer decision |
| D-011 | Every time is shown in the user's own time zone: the Desktop's local zone in the popup, Hermes' configured time zone (else the host's) in messages | maintainer decision |
| D-012 | Simple but well made: the smallest feature set that removes the pain of lost resets; anything else is cut (simplification pass) | maintainer decision |
| D-013 | Masking of account labels is a setting, ON by default (`mask_labels`); off shows full labels in popup and notices. Anything committed (docs, evidence, screenshots, fixtures) is always masked. Supersedes R-006 | maintainer decision |
| D-014 | Keep a local activity log of every action (scan, schedule, reminder, redemption, refresh, failure), sanitized (no tokens, no raw credit ids, labels masked per D-013 rules for files), with retention; plus a History view in the popup and a `history` CLI command | maintainer decision |
| D-015 | Keep a manual **Redeem now** per credit, with a confirmation step, through the same idempotent redeem path and readback | maintainer decision |
| D-016 | Language setting: `auto` (follow Hermes' language), `en`, `pt-BR`; English is the fallback when Hermes' language is neither | maintainer decision |
| D-017 | Quota summary per account is back, compact: plan type (e.g. Student, Plus, Pro, Pro 200, Pro 500, Team, as the backend reports it), and which windows exist (5 h / weekly) with remaining %, the way catalog plugins quota/resetwatch read `/wham/usage`. Banked resets stay the primary content | maintainer decision |
| D-018 | Popup sort control (soonest expiry first by default; also by account) and small quality-of-life touches are welcome if each is tiny and tested; simplicity still rules (no over-engineering) | maintainer decision |
| D-019 | Engineering bar: unit + integration + end-to-end tests, linter and type check where they fit (Python: ruff + type hints checked; JS: node --check and the SDK static checks), PEP 8, small modules; the best possible catalog-compliant plugin | maintainer decision |
| D-020 | The project's agent rules allow the confirmed manual **Redeem now** (D-015); `language` stays `auto` (D-016); automatic redemption is on by default (D-004) | maintainer decision |
| D-021 | Popup: width fits each reset line on one line; time remaining in parentheses (largest whole unit, floored); 'Open Codex usage' link removed (supersedes that part of D-019) | maintainer decision |
| D-022 | Popup layout replaces D-021's one-line width: each reset is a two-line block — line 1 the expiry with the time-left suffix (`Vence qua., 11 de nov., 09:00 (3 dias)`), line 2 the muted rescue time (`Resgate qua., 11 de nov., 08:50`) — inside a fixed comfortable width (400 px, 380 px min, 90vw max). Lines clip with an ellipsis instead of widening the popover. The time-left suffix and the removed 'Open Codex usage' link stay as D-021 left them. Supersedes D-021's width rule | maintainer decision |
| D-023 | `auto_redeem_enabled` (bool, default `true`, label 'Redeem automatically before expiry') is the master switch for automatic redemption, symmetric with `early_redeem_enabled`: off means the planner arms no primary/backup one-shot and `authorize_consume` refuses every automatic role (`primary`, `backup`, `scan`, `early`) with `auto_redeem_disabled`; reminders still go out, the popup says auto-redeem is off, a confirmed manual Redeem now still works, and the next scan re-arms after it is turned back on | maintainer decision |
| D-024 | Popup height is **fixed** on every tab (Accounts, History, Settings) and does not change with content. It is no longer a constant: D-029 measures it at runtime. Five full accounts fit with no scroll, fewer keep the empty space, more scroll inside. Width stays D-022's 400 px. `popoverHeightFor()` in `desktop/plugin.js` takes the measured header, sort row, account block and footer; `ROW_LAYOUT` is only the fallback before the first measurement | maintainer decision |
| D-025 | Settings live in a tab **inside the popup**, rendered by `desktop/plugin.js`, listing the twelve global settings, with account overrides edited in the Per account view, each with the right control (toggle, number, select, text), translated through `ctx.i18n` (en + pt-BR). No Save button: toggles and selects save on change, numbers and text are debounced ~600 ms and flush on blur; saves are silent: there is no "Saved"/"Salvo" note; a save still unanswered after 3 s reads "Checking…"/"Confirmando…" (and "Not confirmed yet"/"Ainda não confirmado" after 60 s, D-033), and "Not saved: <reason>"/"Não salvou: <motivo>" shows only when the engine refuses it; the popup adopts the fresh `StatusDTO` the save returns. Saves go through `POST /api/plugins/reset-rescue/settings` → `reset_rescue.settings.validate_setting` → Hermes' own `hermes_cli.plugins_settings.save_plugin_settings` (never a hand-written `config.yaml`), scoped to the active profile by Hermes' route dependency. The popup's Settings control opens this tab instead of navigating; `config_schema` stays in `plugin.yaml`, so Hermes' English form keeps working | maintainer decision |
| D-026 | `dashboard/plugin_api.py` stays a thin, stable route shim and every request loads the engine through `_engine()`/`_ensure_engine()`, which re-imports `reset_rescue` when any of its `.py` files changed (mtime_ns + size) since the last import; the signature is polled at most once per second, not on every helper import — dropping the `reset_rescue.*` entries under a lock and importing again. Hermes mounts plugin routes once at dashboard startup and never remounts them, so this is what makes a future update apply without a dashboard restart. A package the process already imported is adopted, not reloaded, so a test or the CLI holding a class object keeps it | maintainer decision |
| D-027 | Every pool account is listed in the popup, including accounts with no banked reset. Those show a muted `No resets` / `Sem resets` line and their quota line. In the Soonest view they sort after accounts with resets; in By account they sort by label. This supersedes the D-010 filter (the popup lists accounts with banked resets only). The popup height fits five full accounts, each with two two-line resets and the quota line: `ROW_LAYOUT.accountTwoCredits` 144 px (the reference build), 897 px in total. D-024 is updated accordingly, and the content box caps at `calc(100vh - 80px)` | maintainer decision |
| D-033 | Dashboard routes dispatch through a final GET/POST catch-all and reload handlers by source mtime_ns + size, so future route updates need no restart after this shim is mounted (one initial dashboard restart is needed for pre-shim installs). Global reset restores schema defaults but preserves notify_target/account_overrides/excluded_accounts; reset-all clears every override with explicit nulls and writes excluded_accounts: []; all deltas share the resolved-profile save lock and POST failures return sanitized JSON codes/details. Popup saves are immediate and optimistic with visible failure/timeout; both reset controls require inline confirmation. Settings reads share the save lock; retries reconcile for up to 60 seconds. Resets persist spend-reducing settings before enabling automatic redemption. | maintainer decision |
| D-034 | Settings > Per account is a list of accounts (accordion: one open at a time), replacing the D-030 matrix. A collapsed row shows the masked label, "Follows global"/"Segue o global" or "N custom setting(s)"/"N ajuste(s)", "Paused"/"Pausada" when not watched, and a chevron. An expanded account lists four options, each an SDK SegmentedControl "Default (On|Off)"/"Padrão (Ligado|Desligado)" · On · Off where one click picks the final value (true / false / null = follow global, no cycling): Auto-redeem expiring credits, Early redeem (with the "when weekly quota left ≤ N%" input while early redeem is effectively on; empty = Default, the global value as placeholder), Reminders, Watch this account. The Default label carries the inherited value; an option on Default is muted, an own value is normal text. Clearing a value (Default, "Reset this account"/"Restaurar esta conta", "Reset all accounts to global"/"Voltar todas para o global") shows the inherited global value at once and the reply's `effective` then wins. Watch inheritance: without its own value an account is watched unless `excluded_accounts` names it by account key or by canonical masked label, matched like the engine (`canonical_label`: legacy `d***@example.com`, current `d***@e***.com` and a full address name the same account, D-028). "Reset this account" is always inside the expanded account, disabled with no own settings; "Reset all accounts to global" stays in the tab footer with the two-click confirm. Tooltips are SDK Tips, never a native `title`. Same save path as D-033 (queue, `POST /settings/account`, silent saves); the Settings title shows once, in the popup header. Height stays D-031: the tab scrolls inside it | maintainer decision |

## Engineering decisions
| ID | Decision | Why |
|---|---|---|
| R-001 | Name "Reset Rescue", repo `bwoliveira/hermes-reset-rescue` | short, says what it does |
| R-002 | Scheduling through native Hermes cron jobs owned by the plugin (periodic scan + primary/backup one-shots), output through native cron delivery | only surface that runs with the Desktop closed and delivers notices; verified by an earlier prototype |
| R-004 | Refresh through the `hermes auth refresh openai-codex <entry id>` CLI, not an in-process `CredentialPool` call | supported user-facing surface; same core call that Hermes' own command uses (`hermes_cli/auth_commands.py`); rotation and the auth.json write stay inside Hermes' process |
| R-005 | Use the credential pool, falling back automatically to the active sign-in when no usable pool accounts are available. | the pool covers every `openai-codex` entry; the active sign-in covers a sign-in that never entered the pool |
| R-006 | SUPERSEDED by D-013 — Full account labels in the popup and notices; masking only in logs, history, evidence and commits | several accounts share an initial; both surfaces belong to the user |
| D-028 | Masking hides the domain too (`b***@f***.com.br`, `e***@e***.com`); old-form labels and `excluded_accounts` entries (`b***@gmail.com`) keep matching the same account | several accounts share a domain. Masking domains prevents account labels from revealing organizational affiliation |
| D-029 | The popup height is measured in the browser, not fixed. When the popup opens, and when the text or window changes, the Chip renders one hidden account block with the same `AccountSection` component (two scheduled resets and a quota line) and reads the real header, sort row, block and footer heights. `popoverHeightFor(5, sizes)` adds them up, so five full accounts fit on any machine and a third reset or a sixth account scrolls. Sizes are converted from visual to CSS px under zoom. Re-measured on text change and on resize (`ResizeObserver` on the scroll box). Verified by `tests/desktop/render` in headless Chromium at 13 px and 15 px, run by `scripts/render_test.sh` as the `render` gate step | maintainer decision |
| D-030 | Per-account settings: `account_overrides` (dict keyed by account key; R4: overrides by key only, the label is a masked hint, and after a DB rebuild with a new salt affected accounts follow the global settings until re-set) overrides `monitored`, `auto_redeem_enabled`, `early_redeem_enabled`, `early_redeem_remaining_pct` and `reminders_enabled` per account; `Settings.for_account` gives each decision its effective values; paused accounts (`monitored: false`, also `excluded_accounts`) get `account_paused` for every role; `pool_account_count` and `per_account_available` (2+ accounts or any override); routes `POST /settings/account` and `POST /settings/account/reset`. | maintainer decision |
| R4 | Per-account saves write only that account's delta, serialized per profile home; the persisted fallback label is the canonical masked identity; the POST answers from a fresh service | review finding |
| D-031 | The popup height adapts to the content: `clamp(natural, floor, cap)`. natural = the Accounts view as rendered (header, sort row, listed accounts, footer), read from a hidden copy of that view; floor = header + the first four global setting rows + footer, read from hidden copies of those rows (360 px before the first measurement); cap = `popoverHeightFor(5, sizes)` (D-029). Recomputed when the account list, language, masking or window change, never on a tab switch, so every tab keeps the Accounts height and a longer tab scrolls inside; the footer is pinned to the bottom when the floor leaves room. Five or more full accounts keep the D-029 cap and scroll. Verified by `tests/desktop/render` cases g (1 account), h (2), i (0), j (Settings with 1 account) at 13 px and 15 px | maintainer decision |
| D-032 | The status-bar chip inherits Hermes' status-bar typography instead of choosing its own: it renders a plain `<button>` with Hermes' native item class (`STATUSBAR_ACTION_CLASS`, `apps/desktop/src/app/shell/statusbar-controls.tsx:30-31`; the SDK exports no status-bar component or constant) and the native `<span class="truncate">` label, with no inline font size, weight, line height, family or colour and no SDK `Button` (its `text-xs leading-4 font-medium` and ghost `--ui-text-secondary` made the chip larger and brighter than 'Agents' and 'Memory'). Urgent states use the native classes: `text-primary` (update item, `use-statusbar-items.tsx:116`) when a credit expires within 24 h, `text-destructive` (Agents failed, `use-statusbar-items.tsx:626-629`) on failure; the old bold weight on the warning is gone. A `data` StatusbarItem contribution was not used: Hermes would host the popup in a DropdownMenu instead of our Popover. Verified by `tests/desktop/render/statusbar-font.test.mjs` against Hermes' compiled CSS: computed size, weight, line height, family and colour equal the native items at 13 px, 16 px with another sans font, and 125 % zoom | maintainer decision |
